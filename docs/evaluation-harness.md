# Three-axis model evaluation

This harness combines three complementary measurements for one byte-level model:

1. held-out document bits per byte for general language-model likelihood;
2. HellaSwag completion accuracy for bounded four-way continuation ranking; and
3. LAMBADA exact last-word accuracy for long-context generation.

The suite refuses mixed model fingerprints. Each benchmark keeps its own dataset
identity, sample count, primary metric, direction, and limitation. A suite is
claim-eligible only when all three inputs are eligible. This is a bounded CPU
evaluation, not evidence of general intelligence, GPU performance, production
readiness, lecture viewing, or learner understanding.

## Public LAMBADA source

`config/lambada-test.json` pins the MIT-licensed
[`EleutherAI/lambada_openai`](https://huggingface.co/datasets/EleutherAI/lambada_openai)
revision, the published OpenAI-processed file checksum, and the exact 100-row
dataset-server response used by the protocol. The benchmark follows the original
[LAMBADA last-word prediction task](https://aclanthology.org/P16-1144/).

Fetch the pinned response without committing benchmark text:

```bash
curl -fsSL \
  'https://datasets-server.huggingface.co/first-rows?dataset=EleutherAI%2Flambada_openai&config=default&split=test' \
  -o /tmp/lambada-first-rows.json
sha256sum /tmp/lambada-first-rows.json
```

The SHA-256 must equal
`b304b6afffcc2d23ba8b6a67d16df47c60f7511f8ea2ef60016d331b3a485e15`.
Do not continue if the bytes differ; inspect and deliberately repin the source
instead of silently evaluating different data.

## Run and verify LAMBADA

Use a training source and spec that identify the same model used by the other
evaluations. The command supports a verified local or distributed checkpoint;
without one it reconstructs the deterministic initial model declared by the spec.

```bash
ai-journey-lambada evaluate \
  --dataset-response /tmp/lambada-first-rows.json \
  --protocol config/lambada-test.json \
  --source data/day-19-demo-names.txt \
  --spec config/gpt2-training.json \
  --output artifacts/lambada-evidence.json

ai-journey-lambada verify \
  --report artifacts/lambada-evidence.json
```

The evaluator scores target likelihood with the true preceding bytes, then runs a
separate greedy generation using context and previously generated bytes only.
Persisted rows contain hashes and metrics, not narrative text or generated text.
The report includes exact full-passage and 128-byte context-suffix overlap checks
against the bound training source. A detected overlap blocks the bounded claim.

Compare two models only when they cover identical protocol rows:

```bash
ai-journey-lambada compare \
  --baseline artifacts/lambada-baseline.json \
  --candidate artifacts/lambada-candidate.json
```

## Build the three-axis suite

First create a verified HellaSwag report using
[`docs/hellaswag-evaluation.md`](hellaswag-evaluation.md). Then provide a separate
held-out document file whose nonempty lines are independent documents.

```bash
ai-journey-evaluation-suite build \
  --source data/day-19-demo-names.txt \
  --spec config/gpt2-training.json \
  --heldout-data artifacts/heldout-public.txt \
  --hellaswag-report artifacts/hellaswag-evidence.json \
  --lambada-report artifacts/lambada-evidence.json \
  --output artifacts/evaluation-suite.json

ai-journey-evaluation-suite verify \
  --report artifacts/evaluation-suite.json
```

Keep the held-out file separate from training data. A complete suite does not
erase each component's limitations; it proves only that three bounded evaluators
ran against the same exact model state and their evidence passed local integrity
checks.
